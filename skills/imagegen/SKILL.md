# AIGC 创作与拍照增强

先调用 aigc_create action:capabilities，只使用已配置的能力。该扩展不提供 Codex 内置 image_gen，也不替宿主运行提示词改写模型。调用方式以已挂载工具为准。

## 素材来自哪里

- 人设与认识的人的外观由 Persona 管理。若 Persona 提供 appearance_lookup，按稳定 entity_id 查询并选择需要的正面、侧面、背面参考与版本。
- 游戏 World 提供普通截图和历史场景／镜头信息；需要体素输入时显式请求，保留未知区块与渲染近似说明。
- 独立创作无需游戏。不要读取其他 World 的私有目录、凭据或记忆文件。
- 每张参考明确 role：edit-target／scene-layout／identity／style。场景主图放第一张，人设图随后；设定纸的白底、排版、文字和站姿不属于场景。

## 先决定创作意图

1. 新创作：参考只决定外观或风格，场景可以自主构思。
2. 重绘：先列出必须保留的地标、空间关系、动作、镜头朝向及允许调整的构图。无需机械复制每个像素。
3. 精确编辑：明确只改哪一处，其余内容保持不变。

## 提示词组织

按「场景 → 主体 → 构图与镜头 → 材质和光线 → 保留项／排除项 → 使用目的」组织。具体要求已经清楚时只整理，不擅自加人物、道具、故事、标语或颜色。

游戏重绘可以选择：真实环境材质与自然光照，人物保持二次元脸部辨识度，头发、布料、皮肤与尾巴具有可信质感。风格由 Persona 和用户决定；不要把这个例子变成所有作品的固定风格。

相机的平视／俯视、人物朝向与当时动作以本次截图和采样数据为准。以前生成的图只按指定角色参与参考。去掉 HUD、名字、聊天框、轨迹线、鼠标与浏览器边框。

## 视频与歌曲

- 视频说明镜头、动作、时长、节奏和需要保持的人物外观。先检查供应商是否接受图片参考；文生视频端点不能假装具备人物一致性。
- 歌曲写清风格、乐器、歌词或 instrumental=true。只有供应商明确支持时才提供歌手参考；音频生成成功不能证明是自己的音色。
- 作品生成与舞台播放分别调用。创作室不会自动开播、唱歌或移动人物。

## 提交与验收

用稳定 request_id 提交 aigc_create action:generate。受理只代表任务存在。使用原 id 的 status/read/wait 查询或接收 aigc.job，不能因超时换 id 重投。

wait 的取消只停止等待；cancel 中止本机请求，远端可能仍运行或计费。unknown 先按原 providerRequestId 对账。

read 返回实际成品，inputs 返回原始提示词和参考。检查主体、构图、镜头、文字、材质与保留项；音视频还要实际观看／试听。文件格式通过不等于内容通过。每次迭代针对一个明确问题，保留原图和前一版。

生成物不进入当前游戏事实。长期采纳、人物身份确认与记忆整理由 Persona 决定。

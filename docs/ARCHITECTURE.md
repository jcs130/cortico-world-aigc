# src/contracts.ts、src/core/studio.ts：创作任务与跨 World 边界

## 所有权

| 组件 | 权威数据与职责 |
|---|---|
| Bot 装配 | Persona、Memory、启用的 World、模型连接和演出出口的选择 |
| Persona／Memory | 人格、目标、个人经历、人物身份与参考图版本、创意和采用决策 |
| Minecraft 核心 | 截图、已加载体素、相机、游戏事实与动作证据 |
| AIGC | 图片、视频、歌曲的显式生成任务、供应商、原始输入和作品归档 |
| 演出 World | TTS、口型、实时动作、候选试听、采用和实际播放回执 |

World 之间没有方法调用。Persona 从截图工具和自身 Memory 取得句柄，明确选择参考角色后调用 AIGC；检查作品后，再调用演出或发送工具。句柄由同一宿主解析。跨机器需要显式素材桥及相应访问权限，不能把 log:/mem: 解释为公共 URL。

人物参考辅助函数是可选的 Persona 工具，独立入口 /persona 不加载 World、不调用模型、不读取其他 World。现有 Memory 仍是权威存储；这不是一个新增的人格或记忆服务。

## 源码依赖

contracts → 无框架的类型与协议；core → contracts、文件归档和显式 GenerationPort；mcp → core；Cortico 入口 → core。

core 不导入 Cortico、Minecraft 或演出包。媒体容器校验和 HTTP 字节限制是共享基础函数，供应商适配器依赖它们。FLUX 图构建器与云适配器不互相导入。

## 任务和证据

request_id 对应一个调用意图；job.id 对应创作作业；providerRequestId 是服务端原始请求号；task_id 是宿主提供的关联编号。受理、生成终态、内容采用、播放结束和宿主目标完成各自独立。

供应商明确 FAILED／CANCELED 的回执保留为已确认终态。失联、丢失响应和无法确认的远端状态保留 unknown，禁止自动再次提交。每个任务捕获提交时的供应商配置；新配置只作用于新任务。取消等待与取消本机任务分开，取消本机请求不保证远端停止计算。

终态事件和重复调用回执只带任务元数据与素材编号；read 显式加载原始媒体，inputs 显式读取原文和参考。list 返回短索引。文件 SHA 和原始参考字节保留在作业归档中。MCP 通知包含相同证据和可查询资源地址。

## 模型上下文和演出

AIGC 不启动提示词规划或额外模型循环。宿主写出最终提示词，使用稳定系统前缀；动态场景信息按键替换后放在请求尾部。预算显式包含工具描述、媒体输入估算与输出预留。

只读查询工具不设置执行屏障，也不能提交、取消、采用或播放。生成和取消由动作工具负责；旧查询动作保留为兼容入口。演出当前状态通过事件和只读查询取得，不能把持续变化的状态 JSON 插入系统前缀。

同一播出通道由 Bot 装配选择一个语音／音乐输出。旧 Live2D World、旧私有 3D 原型与新 3D 演出 World 是不同入口；不得同时为同一句话配置自动 TTS。World 内部的音频拥有者只约束该 World，不能证明其他 World 已静音。

骨骼动作需要绑定目标人物的骨架和模型 SHA，其生成、重定向与验收仍由演出领域负责。AIGC 中的视频作品与实时渲染流分别配置，不自动接管游戏或直播。

# EdenLive 实时体素试验，2026-10-20

## 结论

实时输入、增量推理及预览/OBS 浏览器输出链路跑通；画面质量验收未通过。
本次没有替换正式直播画面，没有启动平台推流，也没有重载可米宿主。
这是约 44 秒的有限试验，不能作为长时间直播稳定性的证明。

## 运行边界

- 输入复用现役可米的只读 `ViewerGameplayObserver`，固定原账号 UUID；没有创建另一个游戏登录，也没有控制游戏。
- 使用显式配置的 Minecraft 1.21.1 方块目录、纹理资产及公开体素渲染器。输入是几何代理，不是客户端截图，也没有真实骨骼动作。
- 后端为已有 LightX2V / EdenLive 5B，4 步、INT8 ConvRot DiT/代理编码器、FP8 T5、T5 CPU offload、LightTAE。采用本机原有兼容 `sage_attn2` 预设。
- 输出为同一有界队列的 WebSocket/JPEG 增量帧；预览和 OBS 浏览器页各收到完整输出，没有另起推理会话。有限任务结束后退出，不自动重启。
- GPU 为 RTX 5090 D，32GB。统计按 1Hz 采样，是包含桌面、可米和其他保留服务的整卡数据，不是进程独占数值。

## 画质失败项

1. 固定第三人称相机进入墙体，代理图出现大面积遮挡。模型无法从被遮挡的输入还原当前场景。
2. 锚点提前生成；模型加载期间可米继续移动。静态参考与开播位置发生偏离。
3. 输入局部场景边界可见，地形和人物会漂移，人物有时消失；不能把有效数值或无黑帧当作外观正确。
4. 只有中性人物标记，没有真实骨骼动画，因此生成肢体动作不能用作实际游戏动作的证明。

正式启用前，需要在通用渲染器实现相机避障及局部场景有效性判断，再建立锚点/场景切换的同步策略，并重新做视觉验收。本次不以改提示词掩盖输入问题。

## 其他样本

较早的一轮新官方优化预设在 1280×704 出现过纯黑帧；该轮同时是冻结场景演示，后续还遇到容器回传网络中断。其吞吐不计为可用实时帧率。没有确认是预设、缓存内核或版本配合的哪一项造成，不能据此声称 720p 已修复。

服务器连接曾短时超时，随后 25565、4000 和 8100 均恢复；可米自行重连。宿主和游戏 worker 的进程编号及启动时间保持不变。只读观察端不能提供服务端权威 realm/控制状态证明。

## 离线校验与清理

- Node 语法与 Python 编译检查通过。
- relay 实测：相同 chunk 重投返回复用；ID 内容冲突 409；取消后 late frame 和重新 generating 均 409，没有重复展示或终态复活。
- 首参考原始采样时间、非实时标识和隔离演示标识检查通过。
- 实际测试的两个浏览器页均收到 957 帧且没有解码错误；未启动 OBS 应用或平台广播。
- GPU worker 有限退出；本轮三个试验 relay 和其专属无头浏览器已关闭。现役可米、TTS、3D 演出和容器保留。
